# 客户端手动同步设计

> 文件说明：本文档记录 Flutter 客户端接入服务端同步 API 的第一阶段设计。

## 目标

本阶段让客户端具备可手动验证的多端同步闭环。用户登录后点击同步按钮，客户端把本地文件夹和笔记推送到 Go API，再拉取服务端变更写回本地 SQLite。

## 范围

本阶段包含：

- 新增同步 API 客户端，调用 `POST /api/sync/push` 和 `GET /api/sync/pull`。
- 本地笔记仓库支持列出全部文件夹、全部笔记，以及按 ID upsert 文件夹和笔记。
- 新增同步服务，负责本地模型和服务端 JSON 模型转换。
- 顶部工具栏新增手动同步按钮和同步状态。
- 同步使用当前登录会话的 access token。

本阶段不包含：

- 后台自动同步。
- 增量本地变更队列。
- 冲突副本生成。
- 图片附件同步。
- 删除同步 UI。

## 数据流

1. 用户登录进入笔记界面。
2. 用户点击顶部同步按钮。
3. 客户端读取本地全部文件夹和笔记。
4. 客户端调用 `POST /api/sync/push` 上传全量本地状态。
5. 客户端调用 `GET /api/sync/pull?since=0` 拉取服务端当前状态。
6. 客户端将拉取到的文件夹和笔记 upsert 到本地 SQLite。
7. UI 刷新列表和详情，并显示“同步完成”或错误信息。

## UI 规则

- 顶部工具栏现有 `SQLite 已保存` 徽标扩展为同步状态。
- 同步按钮使用 `Icons.sync_rounded`，同步中禁用按钮并显示旋转含义的文案“同步中”。
- 同步成功显示“已同步”。
- 同步失败显示“同步失败”，并通过 SnackBar 展示可读错误。
- 保持 Calm Cyan 的低调工具型风格，不新增大面积卡片。

## 错误处理

- 网络错误、服务端错误和 JSON 解析错误统一映射为可展示的同步异常。
- 同步失败不影响本地编辑和本地 SQLite 数据。
- access token 过期暂不自动刷新，本阶段显示同步失败，后续接 token refresh。

## 测试策略

- `SyncApiClient` 测试请求路径、鉴权头、JSON 解析和错误映射。
- `SqliteNoteRepository` 测试列出全部和 upsert。
- `NoteSyncService` 测试 push 后 pull 并写回本地。
- Widget 测试同步按钮触发同步并更新状态。
- 全量运行 `flutter --no-version-check test`。
