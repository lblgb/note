# 客户端同步体验和令牌刷新设计

> 文件说明：本文档记录手动同步链路的体验补强和令牌刷新设计。

## 目标

在现有手动同步基础上，补齐用户能感知和能恢复的同步体验。同步不再每次从 `since=0` 全量拉取，而是保存服务端游标；访问令牌过期时先刷新令牌并重试；刷新失败时给出“重新登录”入口。

## 范围

本阶段包含：

- 本地保存同步游标 `serverVersion`。
- 手动同步使用保存的游标执行增量 `pull`。
- 同步成功状态显示同步到的文件夹、笔记数量。
- 同步失败状态区分网络失败和登录失效。
- 访问令牌过期时调用 `/api/auth/refresh` 刷新令牌并重试同步。
- 刷新失败或服务端仍返回未授权时，弹出“登录已失效”对话框，提供“取消”和“重新登录”。

本阶段不包含：

- 自动后台同步。
- 冲突副本。
- 附件同步。
- 复杂同步历史列表。

## 数据流

1. 用户点击“同步”。
2. 客户端读取本地同步游标，默认 `0`。
3. 客户端 push 本地文件夹和笔记。
4. 客户端 pull `since=本地游标` 的服务端变更。
5. 成功后写回本地数据，并保存新的 `serverVersion`。
6. 如果 push/pull 返回未授权，客户端调用 refresh token。
7. refresh 成功后保存新会话，并用新 access token 重试一次同步。
8. refresh 失败时弹窗提示重新登录。

## UI 行为

- 同步中：按钮禁用，状态显示“同步中”。
- 同步成功：状态显示“已同步：X 文件夹 / Y 笔记”。
- 普通失败：状态显示“同步失败”，SnackBar 展示错误。
- 登录失效：弹出对话框：

```text
登录已失效

当前登录状态已过期，请重新登录后再同步。

[取消] [重新登录]
```

- 点击“取消”：关闭弹窗，继续停留在笔记界面。
- 点击“重新登录”：清除本地会话并回到登录页。

## 测试策略

- `AuthApiClient.refresh` 请求和响应解析测试。
- 同步游标本地存储测试。
- `NoteSyncService` 使用游标执行 pull，并在成功后保存新游标。
- `AuthGate` 刷新令牌后更新会话。
- Widget 测试：同步未授权后弹出登录失效对话框；点击重新登录返回登录页。
- 全量运行 `flutter --no-version-check test`。
