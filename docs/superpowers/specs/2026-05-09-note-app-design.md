# 轻量多端同步笔记设计文档

> 文件说明：本文档记录轻量多端同步笔记应用的第一版产品约束、架构设计和工程规范。

## 1. 目标

本项目第一版建设一个本地优先的轻量同步笔记应用，覆盖 Windows 端和 Android 端。用户可以在离线状态下创建、编辑和删除笔记，联网后通过自建 Go 后端在多端之间同步数据。

第一版重点是形成可真实使用的闭环：账号注册登录、文件夹、笔记、图片附件、外部链接、内部笔记链接、离线编辑、多端同步和冲突副本。

## 2. 已确认约束

- 交流、文档和项目说明使用中文。
- 所有文本和代码文件固定使用 UTF-8 编码。
- 代码相关文件开头添加简单文件说明注释。
- 每个方法或函数添加简单注释，说明用途。
- 维护 `docs/` 下的相关文档。
- 使用 git 管理代码和文档。
- 重要功能完成后提交 git 归档。
- 不提交临时会话目录、构建产物、本地数据库和附件数据目录。

## 3. 第一版范围

第一版包含：

- 账号注册、登录、退出登录。
- Windows 和 Android 客户端。
- 文件夹管理。
- 笔记新建、编辑、删除、查看。
- Markdown 作为底层正文格式。
- 编辑器提供图片、外部链接、内部笔记链接插入能力。
- 图片附件保存、展示和同步。
- 外部链接跳转到系统浏览器。
- 内部笔记链接跳转到应用内目标笔记。
- 本地离线编辑。
- 多端同步。
- 冲突时保留两个版本。
- 基础错误提示和同步状态展示。

第一版暂不包含：

- 多人协作。
- 笔记分享。
- 实时协同编辑。
- 富文本块编辑器。
- 标签系统。
- 端到端加密。
- 第三方登录。
- 浏览器 Web 端。
- 反向链接和关系图谱。

## 4. 总体架构

系统由三部分组成：

1. Flutter 客户端  
   覆盖 Windows 和 Android，负责界面、编辑器、本地存储、附件管理、同步队列和同步状态展示。

2. Go 同步后端  
   提供账号认证、设备登记、变更同步、附件上传下载等 API。

3. 本地数据层  
   每个客户端维护本地 SQLite 数据库和本地附件目录。客户端离线时直接读写本地数据，联网后再与服务端同步。

服务端是同步和备份中心，不是客户端操作的唯一数据源。

## 5. 客户端设计

客户端使用 Flutter 开发，一套代码覆盖 Windows 和 Android。

Windows 端布局：

- 左侧显示文件夹树。
- 中间显示当前文件夹下的笔记列表。
- 右侧显示笔记编辑区。
- 顶部或编辑区工具栏提供新建、保存状态、插入图片、插入外链、插入笔记内链、编辑和预览切换、同步状态。

Android 端布局：

- 首页显示文件夹列表和最近笔记入口。
- 进入文件夹后显示笔记列表。
- 点击笔记进入编辑页。
- 编辑页顶部显示返回、更多菜单和同步状态。
- 编辑工具栏提供图片、外链、笔记内链和预览入口。

编辑器采用 Markdown 编辑加预览的混合模式：

- 默认编辑模式用于快速输入。
- 预览模式渲染 Markdown、图片、外部链接和内部笔记链接。
- 插入图片时选择系统图片或文件，复制到应用附件目录，创建附件记录，并插入附件协议链接。
- 插入外链时输入链接文字和 URL。
- 插入内部笔记链接时搜索已有笔记，选中后插入目标笔记 ID 链接。
- 点击外链时调用系统浏览器。
- 点击内部笔记链接时在应用内打开目标笔记。
- 点击图片时预览大图。

## 6. 本地数据模型

客户端本地使用 SQLite 保存结构化数据，附件保存到本地文件目录。数据库只保存附件元数据和相对路径，不保存图片二进制正文。

建议核心表：

- `users`：当前登录用户信息。
- `devices`：本机设备标识、设备名称和平台。
- `folders`：文件夹，支持父子层级。
- `notes`：笔记标题、正文 Markdown、所属文件夹、版本号、删除状态和更新时间。
- `attachments`：图片附件 ID、本地路径、远端对象 Key、大小、哈希和上传状态。
- `note_attachments`：笔记和附件的引用关系。
- `sync_changes`：本地待同步变更队列。
- `sync_state`：当前设备最后同步位置。
- `conflict_notes`：冲突副本记录。

第一版不强制维护反向链接表。内部笔记链接直接存在 Markdown 正文中，后续需要反向链接或关系图谱时再增加索引表。

## 7. 链接协议

外部网页链接使用标准 Markdown：

```md
[官网](https://example.com)
```

图片附件使用内部附件协议：

```md
![图片说明](note-attachment://附件ID)
```

客户端渲染时把 `note-attachment://附件ID` 映射到本地图片路径。如果本地尚未下载附件，则显示占位和下载状态。

内部笔记链接使用稳定笔记 ID：

```md
[目标笔记标题](note-note://目标笔记ID)
```

使用笔记 ID 而不是标题作为真实目标，避免笔记重命名后断链。点击内部笔记链接时，客户端在本地查找目标笔记并跳转。目标不存在、已删除或尚未同步时，显示“目标笔记不存在或尚未同步”。

## 8. 同步设计

同步采用变更日志加版本号的方式。

同步流程：

1. 用户在本地修改文件夹、笔记或附件。
2. 客户端先写入 SQLite 和本地文件，再写入 `sync_changes`。
3. 客户端在有网络且登录有效时批量上传本地变更。
4. 服务端保存变更并生成服务端递增版本。
5. 客户端拉取自己上次同步版本之后的远端变更。
6. 如果远端变更和本地未同步变更修改了同一篇笔记，客户端生成冲突副本，不覆盖任意一方。
7. 图片附件单独上传和下载，并通过哈希避免重复上传。

删除策略：

- 删除笔记使用软删除，写入 `deleted_at` 并同步到其他设备。
- 删除文件夹第一版要求文件夹为空，避免级联删除和恢复逻辑复杂化。
- 删除附件时先检查是否仍有笔记引用；没有引用时标记为待清理，第一版不急于物理删除。

冲突策略：

- 不做最后写入覆盖。
- 不做复杂自动合并。
- 冲突时保留两个版本。
- 冲突副本显示在同一文件夹下，标题加“冲突副本”标识。

## 9. 后端设计

Go 后端第一版职责：

- 账号认证。
- 设备登记。
- 变更同步。
- 附件存储。

建议服务端组件：

- API 服务：Go。
- 主数据库：PostgreSQL。
- 附件存储：可插拔存储层。
- 鉴权方式：Access Token 加 Refresh Token。
- 密码哈希：Argon2id 或 bcrypt。

主要服务端表：

- `users`：账号信息。
- `refresh_tokens`：刷新令牌。
- `devices`：用户设备。
- `folders`：服务端文件夹状态。
- `notes`：服务端笔记状态。
- `attachments`：附件元数据。
- `changes`：服务端变更日志。
- `sync_cursors`：设备同步游标，可选。

主要 API：

```text
POST /api/auth/register
POST /api/auth/login
POST /api/auth/refresh
POST /api/auth/logout

POST /api/devices/register

GET  /api/sync/pull?since=版本号
POST /api/sync/push

POST /api/attachments/upload
GET  /api/attachments/{id}/download
HEAD /api/attachments/{id}
```

## 10. 附件存储设计

附件存储层必须可插拔，业务层不能直接依赖具体文件路径或对象存储 SDK。

建议后端定义统一接口：

```go
type AttachmentStorage interface {
    Save(ctx context.Context, key string, reader io.Reader) error
    Open(ctx context.Context, key string) (io.ReadCloser, error)
    Exists(ctx context.Context, key string) (bool, error)
    Delete(ctx context.Context, key string) error
}
```

第一版默认实现本地文件存储，方便开发和测试：

```text
data/
  attachments/
    用户ID/
      附件ID
```

生产环境可以配置为对象存储实现，例如 S3、MinIO 或兼容 S3 的云厂商对象存储。切换时通过配置选择实现，例如：

```env
ATTACHMENT_STORAGE=local
ATTACHMENT_STORAGE=s3
```

## 11. 错误处理

- 本地编辑失败时提示具体原因，例如数据库写入失败或附件复制失败。
- 同步失败不阻止继续编辑，记录失败状态并允许手动重试。
- 登录过期时自动刷新 Token；刷新失败后回到未登录状态，但保留本地数据。
- 附件上传失败时保留笔记正文，附件标记为待上传，后续重试。
- 附件下载失败时显示图片占位和重试入口。
- 内部笔记链接失效时提示目标笔记不存在或尚未同步。
- 冲突时生成冲突副本，不覆盖任何一方内容。
- 服务端返回统一错误结构，便于客户端展示和日志排查。
