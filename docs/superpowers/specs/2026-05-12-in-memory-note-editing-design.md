# 内存笔记编辑闭环设计

> 文件说明：本文档记录 Flutter 客户端内存笔记新建、编辑和保存阶段的目标、范围和技术设计。

## 目标

本阶段把本地笔记浏览器推进到最小可用编辑闭环。用户可以在 Windows 客户端中基于内存数据新建笔记、编辑标题和正文、保存修改，并立即在列表和详情中看到更新结果。

## 范围

包含：

- 扩展本地笔记仓储接口，支持新建和更新笔记。
- 扩展内存仓储实现，保存运行期间的笔记改动。
- 增加编辑状态，支持查看模式和编辑模式切换。
- 增加新建笔记入口。
- 增加保存和取消编辑动作。
- Widget 测试覆盖新建、编辑、保存和取消。

不包含：

- SQLite 落盘和应用重启后的数据保留。
- 删除笔记。
- 文件夹新建、重命名和删除。
- Markdown 渲染和预览。
- 图片附件。
- 外部链接跳转。
- 内部笔记链接跳转。
- 登录、同步和后端接口调用。

## 架构

继续沿用当前 notes feature 分层：

- `domain`：保留 `Folder` 和 `Note` 模型。
- `data`：`NoteRepository` 从只读接口扩展为内存可写接口。
- `presentation`：`NoteBrowserPage` 负责当前选中状态、编辑控制器和保存动作。

本阶段不引入状态管理库。页面状态仍用 `StatefulWidget` 管理，避免在 SQLite 和同步前引入额外架构复杂度。

## 数据行为

仓储新增两个方法：

- `createNote(folderId, title, content)`：在指定文件夹下创建笔记，返回新笔记。
- `updateNote(noteId, title, content)`：更新已有笔记，返回更新后的笔记；如果笔记不存在则返回 `null`。

内存仓储维护可变的 `_notes` 列表。新增笔记 ID 使用内存自增序号生成，格式为 `note-local-1`、`note-local-2`。更新时间使用可注入的 `DateTime Function()`，默认使用 `DateTime.now`，测试中可以传入固定时间。

## 交互

查看模式：

- 展示文件夹、笔记列表和详情。
- 详情区显示“新建”和“编辑”按钮。
- 没有选中笔记时，“编辑”按钮不可用。

新建：

- 点击“新建”后，在当前文件夹进入编辑模式。
- 标题默认是“未命名笔记”，正文为空。
- 点击“保存”后创建笔记，选中新笔记并回到查看模式。
- 点击“取消”后放弃新建并回到查看模式。

编辑：

- 点击“编辑”后，标题和正文变成可编辑输入框。
- 点击“保存”后更新当前笔记，列表和详情同步刷新。
- 点击“取消”后放弃本次改动，恢复原详情。

## 错误和空状态

本阶段内存仓储不涉及 IO 错误。需要处理：

- 没有文件夹时不允许新建。
- 当前文件夹没有笔记时，仍允许新建。
- 更新笔记时目标不存在，则回到查看模式并保持当前列表状态。

## 测试

Widget 测试覆盖：

- 新建笔记后列表和详情显示新内容。
- 编辑现有笔记后列表标题和详情正文更新。
- 取消编辑后原内容不变。

仓储行为可以通过 widget 测试间接覆盖；本阶段不单独增加仓储单元测试，避免测试范围超过最小闭环。

## 验证方式

```powershell
Set-Location apps/client
flutter analyze
flutter test
flutter run -d windows
```

完成后，用户可以在 Windows 客户端验证新建、编辑、保存和取消编辑流程。数据只在本次运行期间保留。
